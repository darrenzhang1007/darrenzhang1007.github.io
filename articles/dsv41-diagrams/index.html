1. 一页纸调用链速览

  • 动态交互版：打开调用链速览动态查看器（支持调用链动画、节点聚焦、路径追踪及 MLA / MoE / DSpark 分章节播放）

1.1 主调用链

  1. DeepseekV41ForCausalLM 作为 VL 外层包装；纯文本或视觉特征最终都进入 CoreX 版 DeepseekV41LLMForCausalLM。
  2. DeepseekV41LLMForCausalLM.forward() 调用 DeepseekV4Model.forward()，先完成 token embedding（[T,5120]，vocab=129280）。
  3. 若启用 Engram，进入 Decoder 之前整批计算 n-gram hash（2/3/4-gram × 8 head = 24 列）并预取查表结果；注入发生在 L1 / L14 的层入口：先独立 mhc_post 重建四流残差，注入后才执行本层 mhc_pre_delayed，因此 Engram 位于 Attention 之前。
  4. 主干执行 40 个 DeepseekV4DecoderLayer。每层依次执行： - mhc_pre_delayed → attn_norm → MLA（投影 fan-out）→ O Projection - mhc_pre_delayed（把 attention 子层 post 折进 pre）→ ffn_norm → MoE
  5. mHC 在子层外维护 [T, hc_mult=4, hidden_size=5120]；进入 Attention / MoE 前折叠为 [T, 5120]。MoE 输出不在本层做完整 post，而是连同 residual / post_mix / res_mix / ffn_pre 交给下一层的 mhc_pre_delayed（ffn_pre 在下一层接成 pre_mix）。
  6. 第 40 层结束后才显式 mhc_post，再用末层 pre_mix 对 4 条流做 FP32 加权求和坍缩为 [T,5120]（插件用 torch 实现，上游对应 hc_collapse_triton），然后 final RMSNorm → ParallelLMHead，得到 target logits。
  7. 投机解码时，选定层结束后用 mhc_post 重建 aux hidden（再对 hc 流 mean），交给 DSpark。层号来自 dspark_target_layer_ids（基线 0-based 36/37/38）。DSpark 默认 3 个 draft layer；dspark_block_size=5 是 token 块长度，num_speculative_tokens 是建议 token 数，二者都不是网络层数。Draft 由 target 重算 logits 验签后采样。

1.2 Attention 路径

  • attn_gemm_parallel_execute 从同一份 attn_norm hidden fan-out 三路（不是 fused_wqa_wkv → compressor → indexer 串行）：
  • fused_wqa_wkv（W8A8，5120→1792）→ qr [T,1280] + kv [T,512] → q_norm / RoPE / SWA KV insert（SWA 窗 128）
  • kv_score → Compressor（仅 kv-source 层 L2/8/14/20）→ compressed KV cache
  • indexer.weights_proj + 归一化 qr → Indexer（仅 index-source 层 L2/8/14/20/24/28/32/36）→ top-512
  • 两级候选：L20 发布 2048 个候选块（每块 8 个压缩位置），L24/28/32/36 只在候选集中选 top-512。
  • 压缩比按层分三档：L0–L1 纯 SWA、L2–L19 ratio-2、L20–L39 ratio-1；非 source 层复用所属 source 的 cache / top-k。
  • Sparse MLA kernel 吃 Q、SWA KV、compressed KV、top-k；attn_sink（每头一个 FP32 标量，全局 [64]）是该 kernel 的输入，不是 O Projection 前的加法。
  • prefill：flash_mla_sparse；decode：dsv4_flash_mla_with_kv_cache。
  • _o_proj：inverse RoPE → 8 组 wo_a [4096→1024] → wo_b [8×1024→5120]，输出 [T, 5120]；分组布局要求 TP 整除 8。

1.3 MoE 路径

  • ffn_norm 的同一份 hidden 并行进入 Gate 与 Shared Expert；Shared Expert 不经过 Gate。
  • Gate 输出 384 个专家的 FP32 logits，sqrtsoftplus 打分后每 token 选 top-6，驱动 384 个 W4A8 packed routed experts（int4 权重 / int8 激活；gate/up 合并 [5120→2×2304] → SwiGLU/clamp → down [2304→5120]）。
  • Shared expert 为 W8A8 SwiGLU，swiglu_limit=10。
  • 聚合语义：routed_scaling_factor=1.5 已在 top-k 路由权重中计入一次，moe_sum 再加 shared，聚合处不重复乘 1.5。

2.4 图 1 · 模型总览（Top-Level）

2.5 图 2 · DecoderLayer 内部（单层拓扑）

每个 DecoderLayer 由两个残差块组成，hc 流贯穿整个 layer。layers.1 / layers.14 在本层入口、Attention 之前插入 Engram 注入。

hc 流 3 维张量与折叠节点： - residual ∈ R[T, hc_mult=4, hidden_size=5120]：mHC 维护的 3 维张量；x [T,5120] 是子层实际计算的二维激活。 - mhc_pre_delayed 交回 (residual, post_mix, res_mix, x, attn_pre)：x 送往 attn_norm，attn_pre [T,4] 留给本层 FFN 前的 mHC 当 pre_mix。 - 首层没有上一层状态：先在层内把 embedding 广播成 4 条流，并用专门的 hc_attn_fn_broadcast 权重计算 mix 系数。 - Engram 层特殊处理（仅 L1/L14）：注入必须发生在上一子层 post 完成之后、本层 pre 之前，让本层 Sinkhorn 系数看到注入后的残差；因此 Engram 层不能像普通层那样把 post 折进 pre，而是先独立执行一次 mhc_post。

2.6 图 3 · MLA 内部（Multi-Head Latent Attention + Indexer + Compressor）

MLA 用 512 维 latent 同时充当 K/V，并用滑动窗口（128）加压缩检索（top-512）读取历史，不对全部历史做完整注意力。CoreX fork 的主干 cache 为 BF16 稠密行。

MLA 关键点： - 三路 fan-out：同一份 attn_norm hidden 同时进入 fused_wqa_wkv、kv_score、weights_proj，满足多流条件时分别在默认流与 aux 流 0/1 上并发，三者之间没有串行依赖。 - 两种 Q：主注意力 Q 已从 1280 展开为 64×512；Indexer 使用的是展开前的归一化 qr（再投到 32×128）。 - cache 布局：SWA 与压缩 KV 都是 512 维 BF16 稠密行（448 NoPE + 64 RoPE，不另拼 576 维）；Indexer K 为 FP8 + 页尾 FP32 scale。 - latent 两个下游：Compressor 的 latent 一份经 wk 生成 Indexer K，另一份经 insert_cache 发布为压缩 KV，二者可重叠执行。 - attn_sink：每头一个 FP32 标量（全局 [64]，TP 后各 rank 持有本地头部分），作为 Sparse MLA kernel 参数参与 softmax，而不是 O 投影前的加法偏置。 - 短上下文：max_seq_len // ratio ≤ 512 时直接填满 top-k，跳过打分；owns_k 层仍写 K cache。

2.7 图 4 · MoE 内部（384 experts × top-6 + 1 shared）

MoE 关键点： - routed experts 采用 W4A8 packed（int4 权重、int8 激活、TN 布局、iluvatar_quant.version=2）；gate/up 是合并的一次分组 GEMM，down 是第二次分组 GEMM。上游 NVIDIA 路径对应 MXFP4 + MegaMoE。 - shared expert 与 routed 共享输入但走独立 W8A8 MLP，不受 top-6 分发，也不乘路由缩放因子。 - top-k = 6，路由专家 384 个（区别于 V3 系列的 256 / top-8）。 - routed_scaling_factor = 1.5：只在路由权重中计入一次，output = Σ(topk_weights · routed) + shared。 - bias_vl 是图像 sentinel 的路由偏置，作用在 gate 选专家阶段，不在聚合处相加。

5.1 DSpark vs 经典 MTP

DSV4.1 的投机解码草稿模型是 DSpark，不是经典 MTP： - 是独立模型 DSparkDeepseekV41ForCausalLM，不是 target 40 层里的子模块；层号接在主干之后（layers[40..42]）。 - 权重命名空间：mtp.{0,1,2}.*（V4.1 的 Markov 命名为 embed/head，0731 为 markov_w1/w2）。 - 默认 3 层（优先读 n_mtp_layers / num_nextn_predict_layers，缺失时回退 3），MoE 128 专家 / top-3，主干纯 SWA。 - dspark_block_size=5 是一次草稿的 token 块长度；部署可设 num_speculative_tokens，二者都不是层数。 - 与 V4 标准版（deepseek_v4、43 层、hidden 4096）的经典 MTP 不通用。 - has_own_lm_head = False：draft logits 复用 target lm_head，最终由 target 重算 logits 验签。

5.2 全文口径说明

  • 图中 [T, ...] 使用 vLLM 已展平 token 维度。
  • dspark_target_layer_ids 是 checkpoint 配置（基线 0-based 36/37/38），不是实现硬编码。
  • 图只描述 forward 推理结构；权重加载、TP/PP/EP 约束和 CUDA Graph 细节见 README.md 第 7 章。
